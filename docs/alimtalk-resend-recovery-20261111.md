# 알림톡 실패·미접수 재발송 복구 (2026-11-11)

- 확정 실패는 기존 카드의 재발송 및 개별 이력의 재발송 버튼에서 최신 시간표/번호를 확인하는 서버 절차를 거쳐 전송한다.
- 접수번호가 없는 UNKNOWN은 최초 요청 후 10분이 지나고 RECEIPT_NOT_FOUND로 조회된 경우에만 담당자가 솔라피 콘솔의 미접수 확인을 명시할 수 있다. 빈 API 조회만으로 자동 재발송하지 않는다.
- 확인 작업은 새 메시지를 보내지 않고 NOT_ACCEPTED 상태 및 이전 상태/오류, 확인자/시각/근거를 보존한다. 이후 신규 발송은 일반 검증/중복 방지 경로를 이용한다.
- 미접수 확인 시와 실제 발송 직전에 공급자 기록을 재조회한다. 뒤늦은 접수가 발견되면 재발송을 중단한다. 재발송 claim 트랜잭션에서도 원본 상태를 검사한다.
- 재발송에는 retryOf를 저장하고 원본과 한 묶음으로 보여준다. 발송 응답 뒤 저장 오류가 나도 확보한 messageId/groupId를 보존한다.
- 네트워크 장애 자체를 제거하는 기능은 아니다. 운영자 오판을 포함한 불확실성을 안내하고, 불확실한 전송을 자동으로 반복하지 않는다.

검증: 관련 자동 테스트 107개 통과. 외부 통신을 차단한 합성 PC/모바일 화면에서 한 번 클릭 발송, 부분 갱신, 미접수 확인 화면 및 체크 전 발송 금지 검증 통과.

운영 확인: 2026-11-11 21:52 KST에 김강훈 학생 본인(번호 끝 9594)에게 2026-11-12 수업 안내 신규 1건을 발송했다. 개별 이력에서 수신 완료 1건, 확인 필요 0건, 결과 대기 0건을 확인했다. 기존 20:08 요청은 미접수 확인 이력으로 보존됐다. 다른 수신자에게는 발송하지 않았다.

추가 보완: 개별 이력을 열면 해당 학생 카드만 백그라운드에서 갱신한다. 웹훅으로 수신 완료된 경우에도 왼쪽 카드가 접수 상태에 머무르지 않도록 했다. 회귀 테스트를 추가했으며 관련 UI 테스트 22개가 통과했다.
