# 시간표 전달 운영 기록

2026-10-01. **Firebase Functions, GitHub Pages, Apps Script 운영 배포 완료.** 구현 커밋은 `a90e7ef`, Apps Script 운영 버전은 `246`입니다. 공개된 `index.html`과 `handoff.html`이 로컬 검증 소스와 바이트 단위로 일치함을 확인했습니다. 전용 API의 비로그인 요청은 HTTP 401로 거부됩니다.

실제 화면과 서버 로직을 연결한 격리 환경에서 초안 복원, 연결 실패 후 재시도, 제출, 관리자 조회, 제출 버전별 상태를 합성 데이터로 검증했습니다. 운영 브라우저의 새 탭은 로그인이 필요해 실제 계정으로 작성·제출하는 운영 종단 간 검증은 수행하지 않았습니다. 운영 학생 데이터나 시험용 제출 기록은 생성하지 않았습니다.

## 기능과 데이터 경계

로그인한 사용자가 날짜별 수업을 작성하고 명시적으로 전송합니다. 서버 초안은 본인 전용이며 관리자 수신함에는 전송된 버전만 나타납니다. 초안에는 학생 목록, 시간대별 과목, 입력 중인 이름·네 개의 시/분 필드·유형·비고, 수정 대상이 포함됩니다. 입력 후 700ms 대기하여 자동 저장하고 서버 응답 뒤 저장 완료를 표시합니다.

수업이 있는 시간대만 보여 주며 시작·종료는 시와 분을 나누어 입력합니다. 선택 비고는 학생별로, 자유 입력 과목은 시간대별로 관리합니다. 각 시간대는 최대 동시 인원과 막대 하나를 표시하고 중간 인원 변화를 펼쳐 확인합니다. 입력 범위는 08:00–24:00, 날짜당 최대 200건이며 같은 학생의 겹치는 수업을 거부합니다.

전송은 비어 있거나 입력·수정이 끝나지 않은 내용에 대해 거부합니다. 전송할 때마다 제출 데이터 사본을 보존하며 수신함에서 최근 50개 버전을 조회합니다. 관리자는 제출 데이터 원문을 수정하지 않고 버전별 `미확인 / 확인 중 / 반영 완료` 상태와 상태 revision만 갱신합니다. 운영 시간표 반영은 관리자 수동 작업이며 상태 변경이 시간표를 자동 수정하지 않습니다.

## 구성과 권한

- `docs/handoff.html`: 인증된 시간표 안에 열리는 프레임 UI. 독립 실행은 로그인을 대신하지 않습니다.
- `scripts/handoff-bridge.fragment.js`: 부모 시간표가 인증 토큰을 얻어 Firebase API를 호출합니다. 프레임 source·허용 origin·현재 계정 세션을 확인하며 토큰은 프레임에 전달하지 않습니다. 조회 전용 접근과 계정 변경을 차단합니다.
- `handoff-functions/index.js`: Firebase ID 토큰의 유효성·취소 여부를 확인하고 서버의 계정·앱 권한으로 접근을 결정합니다. `core.js`가 검증·revision·작업 ID 재시도·관리자 상태 처리를 담당합니다.
- `liveTimetableHandoffDays/{date}/teachers/{uid}`: 본인 초안과 최신 제출 메타데이터. 하위 `versions/{operationId}`에는 제출 원문과 변경 가능한 관리자 상태를 둡니다.
- Firebase 프로젝트 `fir-lms-prod`, Functions codebase `live-timetable-handoff`, 리전 `asia-northeast3`, HTTPS 함수 `timetableHandoffApi`. 전달 데이터는 Firebase API → Firestore 경로만 사용하며 GAS·Sheets를 거치지 않습니다.

활성 계정 및 앱 사용 권한을 서버에서 검사합니다. 관리자는 ADMIN 또는 계정·시간표 관리 권한을 가진 STAFF로 판정합니다. 클라이언트가 보낸 역할을 신뢰하지 않습니다. 기존 Firestore 규칙의 해당 경로 기본 거부를 읽기 전용으로 확인했으며 규칙 배포는 하지 않았습니다. 브라우저의 Firestore 직접 접근을 열지 않고 Admin SDK 호출에 앞서 API가 소유권·관리자 권한을 검사합니다.

## 저장 실패와 충돌

초안 저장을 직렬화하고 같은 작업 ID·내용으로 재시도합니다. 제출 재시도도 기존 작업 ID를 유지해 중복 버전을 방지합니다. 서버 revision이 다르면 덮어쓰지 않고 충돌을 알립니다. 사용자는 현재 입력을 확인한 뒤 명시적으로 서버 초안을 다시 불러옵니다. 저장 실패 시 입력은 현재 창에 남지만 서버에 저장됐다고 표시하지 않습니다. 관리자 날짜 조회 실패 시 이전 날짜 수신함을 비워 혼동을 방지합니다.

## 릴리스 순서

프로젝트 루트에서 전용 codebase만 배포합니다.

```sh
npx firebase-tools deploy --config firebase.handoff.json --project fir-lms-prod --only functions:live-timetable-handoff --non-interactive
```

함수 배포 성공과 인증 없는 요청 거부를 확인한 뒤 기존 프로젝트 절차로 GitHub Pages 및 clasp 배포를 진행합니다. 프레임 파일과 부모 브리지가 함께 공개되는지 확인하고, 승인된 테스트 계정으로 초안 복원·명시적 제출·관리자 버전 조회·상태 변경을 확인한 뒤 릴리스 완료를 기록합니다. 이 명령은 다른 Functions codebase나 Firestore 규칙을 배포하지 않습니다.

`docs/`는 공개 배포 대상입니다. 문서·HTML·테스트 증거에 인증 토큰, 서비스 계정 키, 비밀번호, 실제 학생 이름·비고·수업 데이터를 넣지 않습니다. 공개 검증 예시는 합성 데이터만 사용합니다.
