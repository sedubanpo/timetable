# 라이브 시간표 렌더링 성능 점검 (2026-10-17)

## 확인한 병목과 수정

- 검색 루프에서 `innerText` 읽기와 DOM 수정이 번갈아 실행되어 동기 레이아웃 계산이 반복됐다. 텍스트를 먼저 일괄 읽고, 필터 및 강조 표시를 적용하도록 변경했다. 검색 해제 시 불필요한 텍스트 읽기와 DOM 정규화도 생략한다.
- 매초 시계 업데이트가 시간표 좌표 계산 및 현재 시간 셀 스타일 변경을 호출했다. 시계는 초 단위로 유지하고 시간표는 분 변경, 데이터 렌더링, 검색, 창 크기 변경, 스크롤 때 갱신한다. 연속 스크롤 이벤트는 프레임당 한 번 처리한다.
- 비활성 탭의 시계 작업을 중단하고 돌아오면 즉시 현재 시간에 맞춘다.
- Google Fonts의 Pretendard CSS 요청이 실제 HTTP 400을 반환했다. 렌더링을 막는 해당 링크를 제거했다. 카드에서 사용하는 로컬 Pretendard와 PNG 생성 전 폰트 로딩 대기는 유지한다.
- 기존 데이터 요청 병합, 캐시, 인증, 출결 실시간 연결과 데이터 갱신 주기는 변경하지 않았다.

## 수정 전후 비교

Chromium, 1440×1000, 14개 강의실·13개 시간대·1,274개 항목의 합성 데이터. 동일한 실제 페이지 코드에서 학생·과목·강사 검색, 결과 없음 및 검색 해제를 순서대로 실행했다. 외부 요청은 차단했고 운영 데이터는 읽거나 수정하지 않았다.

검색 결과 수와 강조 표시 수는 수정 전후 동일했다. 이 수치는 로컬 합성 데이터 측정이며, 실제 Windows PC나 운영 서버의 로그인/시트 응답 시간에 대한 보장이 아니다.

## 검증

- `scripts/timetable-render-performance.mjs`: 검색 결과·강조 해제, 시간 변경, 시간 표시 켜기/끄기, 연속 스크롤 병합, 비활성 탭 복귀, 모바일 강사 검색.
- 기존 성능 세부 검사 7종: polling, auth, card history, discovery, enrollment, server, client 모두 통과.
- `student-card-browser.mjs`: 수업 병합/공강, 비고, 발송 사유, 이미지 복사와 PNG 저장, 별도 약도 복사/안내 상태.
- `visitor-media-browser.mjs`, `staff-toolbar-browser.mjs`: 배너, 조회용 화면, 도구 모음, 반응형 배치.
- Firebase 카드, 카드 신뢰성, 데스크 권한, 조회용 강의실 상태 검사 통과.
- 두 HTML 진입점의 인라인 JavaScript 문법과 이번에 변경한 공통 함수의 일치 확인.

기존 `performance-checks.cjs` 전체 묶음은 위 성능 세부 검사 후 `review-checks.js`의 전체 HTML 동일성 검사에서 중단된다. 동일 실패가 수정 전 HEAD에도 있음을 확인했다. 전체 파일을 덮어써 기존 호스팅별 차이를 제거하지 않았다. 따라서 전체 묶음 전체가 통과했다고 간주하지 않는다.

재현: `PLAYWRIGHT_MODULE`에 설치된 Playwright 모듈 경로를 지정하고 `node scripts/timetable-render-performance.mjs` 실행. 수정 전 HTML과 비교할 때는 `PERF_BASELINE=1 PERF_HTML=/path/to/before.html`, JSON 저장 시 `PERF_OUTPUT=/path/to/result.json`을 사용한다.
