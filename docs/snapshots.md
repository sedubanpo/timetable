# 시간표 스냅샷

## 구현

- Firebase Functions의 `timetableSnapshotEveryTwoHours`가 한국시간 00·10·12·14·16·18·20·22시 정각에 Apps Script 원본을 새로 읽어 한국시간 오늘·내일을 저장한다. 브라우저가 필요하지 않다.
- `timetableSnapshotApi`는 별도 HTTPS 조회 경로다. 조회는 Apps Script를 호출하지 않는다. 관리자 수동 저장만 원본을 호출한다.
- 날짜 화면 진입과 동시에 저장본과 원본을 병렬 조회한다. 저장본이 먼저 도착하면 즉시 표시하며 원본 성공 시 실시간 표시로 전환한다. 원본 실패 후에는 기존 60초 점검 주기에 다시 시도한다.
- 저장본은 서버가 확인한 날짜/시트로 구분한다. 2시간 이상 경과 시 경고하고 24시간 초과 또는 잘못된 형식은 제공하지 않는다. 메모·출결 전달함은 포함하지 않는다.
- 학생 정보가 있는 원본은 서버 전용 Firestore `liveTimetableSnapshots`에만 보관한다. 클라이언트 직접 읽기/쓰기 규칙을 추가하지 않는다. API에서 매 요청 Firebase ID token(폐기 여부 포함), ACTIVE 상태, 앱 접근 권한을 검증한다. 강사는 본인 이름과 단일하게 매칭된 수업 셀만 받는다. 관리자의 강사 미리보기도 필터링한다. 조회용 2371은 기존 조회 화면 권한을 유지하되, 서명된 6시간 유효 토큰으로 접근한다. 전체 강의실 응답에는 학생/비고가 없다.
- 수동 저장은 ADMIN만 허용한다. 실제 화면의 학생 데이터를 업로드하지 않으며, Apps Script가 반환한 서명 요청의 결과만 저장한다.
- 전역 쓰기 임대로 자동/수동 저장 겹침을 막는다. 불완전·실패 응답과 오래된 응답은 마지막 정상본을 덮어쓰지 않는다. 저장 시점은 원본 읽기 시작 시각이다.

## 배포 설정

1. 32자 이상의 충분히 무작위인 동일 비밀값을 Apps Script 프로젝트 속성 `TIMETABLE_SNAPSHOT_SECRET`과 Firebase Secret Manager의 같은 이름에 설정한다. Git, 프런트엔드, URL, 터미널 출력에 값을 남기지 않는다. 이 값은 서버 간 요청과 조회용 토큰의 서명에만 쓴다.
2. 현재 운영 Firestore 규칙에서 `liveTimetableSnapshots`와 `liveTimetableSnapshotJobs`가 모든 클라이언트에 대해 읽기/쓰기 거부되는지 확인한다. 공개 접근을 허용하지 않는다. Functions 실행 서비스 계정에 해당 프로젝트 Firestore/Secret Manager 접근 권한이 필요하다.
3. `snapshot-functions`에서 `npm ci`를 실행하고, 이 저장소의 `firebase.snapshots.json`으로 새 codebase만 배포한다: `firebase deploy --config firebase.snapshots.json --project fir-lms-prod --only functions:live-timetable-snapshots`. 기존 S-LMS functions/codebase/rules를 배포하거나 삭제하지 않는다. Cloud Scheduler/Functions 사용료가 발생할 수 있다.
4. Apps Script 및 GitHub Pages 변경도 함께 배포한다. 조회용 계정은 새 서명 토큰을 받기 위해 다시 로그인한다.
5. 관리자 저장 버튼으로 성공본을 생성한 뒤, 자동 스케줄의 성공과 데이터 생성시각을 확인한다. 읽기 API의 401/403, 강사 필터, 오늘/내일 날짜, 저장 실패 시 기존본 유지, 브라우저 지연 시 저장본 표시 및 복구를 운영 계정으로 확인한다.

정적 페이지 변경만으로 자동 저장이 켜지지 않는다. Secret/Functions/Scheduler 설정과 최초 저장 성공을 모두 확인한 후 활성화 완료로 보고한다. 새 로그인 자체가 Apps Script 장애로 실패하는 문제나 아직 저장하지 않은 날짜는 이 기능으로 복구하지 못한다.

### 구현

- 인증된 관리자 전체 시간표 조회에서 원본 서버가 이미 읽은 데이터로 서명된 저장용 응답을 만든다. 추가 시트 읽기는 없다. 강사 필터 조회/익명 응답에는 첨부하지 않는다.
- 수동 저장 시 같은 계정·같은 날짜의 정상 실시간 조회본이 있고 조회 후 2시간 이내이면 이를 Firebase로 보낸다. Firebase가 현재 ADMIN 권한, 서명, 용도, 날짜, 시간, 스키마, 크기를 확인하고 저장한다. 화면에서 변경한 데이터나 백업 화면 자체를 신뢰하지 않는다.
- 조회본이 없거나 오래됐으면 기존 원본 재조회 저장을 유지한다. 서명 검증 실패 시 원본 재호출로 자동 우회하지 않는다. 같은 조회본 재전송은 이력을 중복 생성하지 않으며 더 최신 백업을 덮지 않는다.
- 실제 저장 시각과 원본 조회 기준 시각은 분리한다. 화면 저장 직전의 스프레드시트 수정까지 포함한다고 보장하지 않는다. 최신 수정이 필요하면 먼저 명시적으로 새로고침한다.
- 최신 백업과 최근 50건의 성공 저장 메타데이터를 하나의 Firestore 트랜잭션으로 기록한다. 변경 건은 직전 백업 대비 시간·강의실 칸 수, 최초 저장은 별도 표시, 변경 없는 새 조회본 저장은 0건이다. 입력자는 서버에서 확인한 계정 이름(자동 작업은 `자동 저장`)이며 시트 실제 수정자는 아니다.
- 이력 조회는 ADMIN만 가능하고 원본 Apps Script를 호출하지 않는다. 기존 서버 전용 컬렉션을 이용하므로 새 Firestore 허용 규칙이나 인덱스가 필요 없다. 학생 데이터/서명/비밀값은 이력 응답에 포함하지 않는다.
- 이력은 복원 가능한 과거 원본 전체가 아닌 저장 메타데이터다. 기존 저장본은 유지하며 도입 전 변경 수/입력자는 복원하지 않는다. 실패 시도는 성공 이력에 포함하지 않는다.
- 저장 후 날짜 목록 갱신이나 잠금 해제에 실패해도 이미 완료한 저장을 실패로 표시하지 않는다. 잠금은 기존 3분 만료를 유지한다. 원본 요청 제한과 허용된 export 실패 분류를 구분하되 원문/개인정보는 로그에 남기지 않는다.
- 실시간/백업 표시 옆 40px 조회 아이콘 → native dialog. 데스크톱은 표, 390px 모바일은 이름표가 붙은 행으로 표시한다. 조회 중/오류/빈 이력/도입 전 백업/다시 조회, Esc·닫기·포커스 복귀, 로그아웃·날짜 전환·늦은 응답 처리를 포함한다.

### 대안 판단

1. **현재 적용 후보:** 서명된 정상 조회본 저장. 추가 원본 요청을 없애 수동 저장의 독립 실패 경로를 줄인다. 브라우저를 열지 않는 자동 저장에는 이점이 없다.
2. **자동 저장도 분리해야 할 때:** Firebase가 Sheets API로 대상 탭 범위의 `FORMATTED_VALUE`를 직접 읽고 기존 파서와 같은 JSON을 생성하는 방식이 적합하다. 원본 시트를 서버 계정에 읽기 권한으로 공유하고 파서 동등성 검증이 필요하다. 권한 변경 및 새 경로는 이번에 적용하지 않았다.
3. **xlsx:** 비상 수동 반입용으로는 가능하지만 자동 기본 경로로는 권장하지 않는다. 내보내기·업로드·해석 단계가 추가되고 날짜/버전/수식 표시값/권한 검증이 별도로 필요하다. Google Drive `files.export`는 문서 전체를 MIME 형식으로 내보내며 개별 탭 선택 인자가 없다. Sheets API는 탭/범위를 지정해 읽을 수 있으므로 이 앱의 JSON 백업에는 더 직접적인 경로다.

## 2026-09-30 07:06 KST: 한글 서명 인코딩 오류 수정 (Apps Script v244)

- 배포 후 07:01:57 수동 원본 저장에서 `snapshotSourceRejected / UNAUTHORIZED`, 07:02:01·07:02:29 조회본 저장에서 `INVALID_RECEIPT`가 확인됐다. 두 Firebase 함수는 동일 Secret Manager 버전 1을 참조했다. 비밀값 내용은 조회하거나 변경하지 않았다.
