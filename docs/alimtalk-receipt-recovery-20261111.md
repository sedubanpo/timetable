# 알림톡 접수번호 연결 복구 — 2026-11-11

## 확인 범위와 결과

- 운영 Firestore의 2026-01-01~2026-11-12 수업일, 반포관 학부모·학생 실제 발송 기록 182건 점검. 실제 기록은 11/11 88건, 11/12 94건.
- 접수번호가 없는 기록 2건 발견: 김태훈 11/11 학부모, 김강훈 11/12 학생.
- 김태훈: 번호·시각·customFields.timetableKey가 일치하는 원본 ATA 1건을 솔라피에서 확인. 접수번호 연결 복구, 상태 ACCEPTED(2000). 수신 완료로 간주하지 않음.
- 김강훈: 해당 번호의 요청 시각 전 1분~후 10분 조회에서 접수 기록 없음. UNKNOWN 유지, RECEIPT_NOT_FOUND와 조회 시각 기록. 미발송이나 실패로 단정하지 않음.
- 복구 후 전체 재점검: 접수번호 미연결 1건(김강훈). 메시지 추가 발송 0건.

## 변경

- 접수번호가 없어도 저장된 수신번호·요청 시각으로 후보를 읽고, 원본 ATA·고유 발송 식별자·번호·시각이 정확히 일치하는 단일 기록만 연결.
- 최대 100건씩 3페이지. 중복 후보, 잘못된 식별자, 불완전 조회는 연결 중단. 조회 결과가 비어도 자동 재발송하지 않음.
- 발송 응답 실패 직후 읽기 복구 1회. 이력 조회에서도 1분이 지난 접수번호 누락 건을 최대 5건 자동 재확인. 수동 결과 갱신도 ID 없는 건을 처리.
- 기존 재발송 방지와 수신 완료 판정 유지. 조회용 접수번호 복구와 실제 발송을 분리.
- 화면에 접수 기록 연결 필요, 접수 기록 미발견, 최근 조회 시각 표시. 접수가 확인되지 않은 건에 "접수되었으나"라는 표현 사용 중단.

## 검증

- 알림톡 서비스·공급자·일괄 발송·UI·HTTP·런타임·전송 어댑터 테스트 97개 통과.
- PC 1440×1000 / 모바일 390×844 네트워크 차단 합성 데이터 브라우저 검증 통과.
- 기존 기록 복구는 솔라피 GET과 Firestore updateTime 조건부 갱신만 사용.

API 근거: [솔라피 메시지 목록 조회](https://solapi.com/developers/api/msg-getList). 수신번호·기간 필터와 페이지네이션 사용. customFields는 반환된 후보의 일치 검증에 사용하며 검색 조건으로 가정하지 않음.
